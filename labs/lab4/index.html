Introduction

In this lab, we leveraged the MCU aboard the MicroP’s Dev Board, particularly the STM32L4xx model. Utilizing this, we’re able to control the timer logic to function like a counter in order to trigger an output at a certain frequency. This is done via the TIM2 register built into the MCU as well as initiating the GPIO B pins to output a signal that powers a speaker at the desired frequency. With all these puzzle pieces, we can have the speaker play an array of notes and make a tune.

I spent approximately 14 hours in this lab all together including familiarizing myself with the idea and a whole lot of debugging

Design and Testing Methodology

Using SEGGER Embedded Studio, the logic of this lab was contained in a header file and a main file. The header file is essentially a library pointing to the addresses of the MCU so the main logic can leverage several registers. The ones of note for this lab are the RCC, TIM2, and GPIOB register.

There are many timers onboard the MCU but TIM2 has 32 bits and is generally recommended so overflow doesn’t occur and we can create a constant (via PSC) to specify our frequency through altering the ARR and SRC.

Naturally, we want a system that can relate pitch and duration to timer configurations and that can create 220 Hz and 1000 Hz pitches within 1% accuracy. A lot of calculations are involved in this analysis but logically:

MAX DURATION

For maximum delay/duration, the delay is the inverse of frequency (T = 1/f). Using our maximum frequency to get the maximum number, we do 1/(1.164 x 10^-5 Hz) which is 85,900 seconds or 23.86 hours.

MIN DURATION

For minumum the same principle applies but instead we do 1/(25kHz) which means the minimum delay would be about 40 microseconds.

MINIMUM FREQUENCY

The timer frequency is derived by f_out=(f_clk)/(2(PSC+1)(ARR+1)). The dividing by 2 is due to the nature of toggling. This is why the code uses 20MHz rather than 40MHz. Given that f_clk = 40 MHz and PSC=39, the denominator is 80(ARR+1) and we should set ARR to (2^32)-1.

Therefore, f_min=(40MHz)/(80(2^32)) or 1.164 x 10^-5 Hz

MAX FREQUENCY

Referring to the code below, since PSC = 39, let’s say the code has already set the Auto-Reload Register (ARR). For the case in the maximum frequency, ARR should be equal to 1. Using the equation above:

f_max=(40MHz)/(160)= 25 kHz

VERIFY 1% FREQUENCY ACCURACY

To be accurate, we must minimize error. What IS error in this application? Error is defined by the way ARR rounds so relative error Epsilon = 1/(2(ARR+1))

To satisfy Epsilon <= 0.01, this means that 1/(2(ARR+1)) <= 0.01. Meaning ARR+1 >= 50, meaning ARR >= 49.

In Resources below, I linked the formula for the Desmos calculations but to verify for 1000 Hz and 220 Hz:

f = 1000 Hz

ARR = 2000000/(40(1000)) - 1 = 49 and since 49 >= 49, the 1000 Hz note is definitely within 1% accuracy.

f = 220

ARR = 2000000/(40(220)) - 1 = 226.273 and since 226.273 >= 49, the 1000 Hz note is definitely within 1% accuracy.

Additional frequencies and their ARR values are in the Desmos calculator.

The reason that 220 and 1000 are not sufficient is because ARR is a constant and every frequency value evaluated against it would have a different remainder to account for. This means it can’t be cleanly divided and it’s possible a frequency could end up off and so error must be evaluated across every note between 220 Hz and 1000 Hz.

void delay(uint32_t ms) {
    TIM2_reg->ARR = 2000000/(1000*(40))-1; //default delay will be 1000 Hz
    TIM2_reg->CNT = 0;
    for (int i = 1; i <= ms; i++) {
     while(!(TIM2_reg->SR & 1)) {}
    TIM2_reg->SR &= ~(1<<0);
    }
}

void play(int frq, int ms) {
    TIM2_reg->ARR = 2000000/(frq*(40))-1;
    TIM2_reg->CNT = 0;
        for (uint32_t i = 1; i <= ms; i++) {
        while(!(TIM2_reg->SR & 1)) {}
        TIM2_reg->SR &= ~(1<<0);
        GPIOB_reg->ODR ^= (1<<SPK);
        }
}

void lay(int ms) {        //get it? lay as in rest?
    TIM2_reg->CR1 &= ~0x01; //Disable Timer since that's the CEN bit
    GPIOB_reg->ODR = ~(1 << SPK);
    delay(ms);
}


int main(void) {

    int i = 0;

    RCC_reg->AHB2ENR |= (1 << 1); //Bit 1 is GPIOBEN, fits our GPIO B specs
    RCC_reg->APB1ENR1 |= (1 << 0); //Bit 0 is TIM2EN

    GPIOB_reg->MODER &= ~(3 << (SPK * 2)); //Speaker general purpose output
    GPIOB_reg->MODER |= (1 << (SPK * 2));

    TIM2_reg->PSC = 39;  //Prescaler divider const. for frequency calcs 
    TIM2_reg->CR1 |= 1; //CEN as specified before

    while(!(notes[i][0] == 0 && notes[i][1] == 0)) {
        int frq = notes[i][0]; //assigning freq to the first element
        int del = notes[i][1]; //assigning delay duration to second element
        if (frq == 0) {
        //lay(del);
        delay(del*2);
    }
    else {
        uint32_t ms = frq*del/500;
        play(frq, ms*0.80);
        //TIM2_reg->CR1 |= (1 << 0); //Enable CEN
        delay(ms);
    }
    i++;
    GPIOB_reg->ODR = ~(1 << SPK); //Toggling to create the square wave
    }
}

For clarity, the prompt was as follows:

What timers should I use on the STM32L432KC to generate frequencies ranging from 220Hz to 1kHz? What’s the best choice of timer if I want to easily connect it to a GPIO pin? What formulae are relevant, and what registers need to be set to configure them properly?

I decided to prompt Gemini via the Harvey Mudd license (as to not train the AI) and I was presented with the “Initial Prompt” block seen above. Notably, it is comprehensive and covers a lot about timer selection and some of the information I cam across reading the manual. The AI does conclude that TIM2 is ideal for practically the same reason I described about it being 32-bit. However, it instead opts for pin A0 because it supports Alternate Function 1. I instead went the route of using GPIO B and just declaring it as a general purpose output but I can see how PA0 also makes sense and maybe even be more effective since it’s not paired with an LED and AF1 seems to be well equipped for this purpose. It also uses the same logic to enable the clock registers but has to use GPIOA->MODER and declare that as Alternate Function mode. When giving it the files, it functioned more as a table of contents with a summary rather than pointing me to specific addresses and telling me what to do about those sections. I can see why this may be helpful though.
